# Spec 0004a: v05.1 Source Processing Hardening

## Status

Active

## Version Naming

This spec uses `v05.1`.

- Do not use `v051` for this version.
- Documentation filenames should use `v05.1`, for example `0004a-v05.1-source-processing-hardening.md`.
- Python test module filenames should use `v05_1` because `.` is not safe in importable module names, for example `tests/test_v05_1_lodestone_extractor.py`.

## Scope

v05.1의 목표는 v0.5 Source Processing Pipeline을 실제 FFXIV Lodestone 7.5 패치노트 저장 과정에서 드러난 문제 기준으로 안정화하는 것이다.

v0.5는 다음을 완료했다.

- `tools/process_source.py`를 공식 source 처리 entrypoint로 고정
- `text_note`, `markdown_file`, `plain_text_file`, `url` 처리
- Local Storage ingest
- canonical path 기반 `source_id` upsert/update
- wiki/FTS/graph rebuild
- Notion update payload 생성
- OpenClaw source processing skill/runbook/spec/handoff 문서화

v05.1은 새 ingest 기능을 늘리는 단계가 아니다. v0.5를 실제 운영 가능한 수준으로 hardening하는 단계다.

최종 목표는 다음이다.

- Lodestone 패치노트/뉴스 페이지 본문 추출을 안정화한다.
- `process_source.py`만 공식 source 처리 entrypoint로 사용하도록 문서와 테스트로 고정한다.
- `ingest_local.py`, `local_rebuild.py`, `status_notification.py` 직접 호출 혼동을 방지한다.
- `notion_update` payload와 실제 Notion DB write의 경계를 명확히 한다.
- 7.5 패치노트 저장 과정에서 발생한 실수를 회귀 테스트로 막는다.

## Background

v0.5의 공식 source 처리 흐름은 다음이다.

```text
사용자 source 제공
-> OpenClaw가 source_type/category/title 판단
-> tools/process_source.py 실행
-> fetch 또는 local file read
-> tools.ingest_local.ingest_source()
-> tools.local_rebuild.rebuild_after_ingest()
-> wiki/FTS/graph rebuild
-> tools.status_notification.build_notion_status_update()
-> stdout JSON result 출력
```

v0.5 완료 후 7.5 패치노트를 KB에 넣는 실제 작업에서 다음 문제가 관찰되었다.

### Lodestone HTML 추출 문제

관찰된 현상:

- generic readability extractor는 본문을 안정적으로 추출하지 못했다.
- `curl + pandoc` 방식은 HTML noise가 많이 섞였다.
- navigation, footer, share button, script 주변 텍스트가 본문에 섞였다.
- Lodestone HTML에서 `news__detail__wrapper` div를 직접 찾아야 본문 추출이 안정적이었다.

원인:

- FFXIV Lodestone 공식 페이지는 일반 문서형 HTML과 구조가 다르다.
- generic readability extractor만으로는 본문 영역을 안정적으로 특정하기 어렵다.
- 패치노트는 이 프로젝트의 핵심 source 유형이므로 domain-specific extractor가 필요하다.

### `markdown_file` Interface Confusion

다음 호출은 파일 내용을 읽는 것이 아니라 경로 문자열 자체를 body로 저장할 수 있다.

```bash
python tools/ingest_local.py --source-type markdown_file --body "/path/to/file.md"
```

정상 경로는 다음이다.

```bash
python tools/process_source.py --source-type markdown_file --local-path "/path/to/file.md"
```

`ingest_local.py`는 low-level ingest helper다. `ingest_local.py`의 `--body`는 이미 읽힌 body text를 받는다.

### `local_rebuild.py` and `status_notification.py` Library-Only Confusion

`local_rebuild.py`와 `status_notification.py`는 normal source processing을 위한 standalone CLI가 아니다.

정상 호출 경로는 다음이다.

```text
process_source.py
-> local_rebuild.rebuild_after_ingest()
-> status_notification.build_notion_status_update()
```

필요하면 별도 debug CLI인 `tools/rebuild_source.py` 또는 `tools/build_status_payload.py`를 만들 수 있다. v05.1에서 debug CLI 추가는 선택 사항이며 필수는 아니다.

### Notion Auto-Update Boundary Confusion

`process_source.py`는 Notion API를 직접 호출하지 않는다. `notion_update` payload만 생성한다.

실제 Notion DB write는 OpenClaw 또는 별도 Notion control layer가 수행해야 한다.

### Entrypoint Boundary Weakness

v05.1은 다음 역할을 명확히 고정한다.

| File | Role | Direct User/OpenClaw Invocation |
| --- | --- | --- |
| `tools/process_source.py` | 공식 source processing CLI | yes |
| `tools/fetch_url.py` | URL fetch/extract helper | no, except tests/debug |
| `tools/ingest_local.py` | Local Storage ingest helper | no |
| `tools/local_rebuild.py` | rebuild library helper | no |
| `tools/status_notification.py` | Notion/status payload helper | no |
| OpenClaw Notion adapter | `notion_update` payload를 실제 Notion DB에 write | yes, outside `process_source.py` |
| `tools/rebuild_source.py` | optional source_id rebuild debug CLI | optional |
| `tools/build_status_payload.py` | optional payload debug CLI | optional |

## Contract

### Official Entrypoint

Allowed normal source processing commands:

```bash
python tools/process_source.py --apply --source-type text_note ...
python tools/process_source.py --apply --source-type markdown_file --local-path ...
python tools/process_source.py --apply --source-type plain_text_file --local-path ...
python tools/process_source.py --apply --source-type url --url ...
```

Disallowed for normal OpenClaw source processing:

```bash
python tools/ingest_local.py --source-type markdown_file --body "/path/to/file.md"
python tools/local_rebuild.py
python tools/status_notification.py
```

Manual debugging may use shell commands, but committed workflow must use tested Python code.

### URL Extraction Routing

HTML extraction should be routed by URL/domain.

```text
if URL is Lodestone news/detail/patch-note page:
    use Lodestone extractor
else:
    use generic HTML extractor
```

Required content-type behavior:

- `text/html` + Lodestone URL -> `extract_lodestone_article()`
- `text/html` + non-Lodestone URL -> existing generic HTML extraction
- `text/plain`, `application/json`, `+json` -> unchanged text handling
- unsupported content type -> error
- empty body -> error

### Lodestone Extractor API

Required new files:

```text
tools/extractors/__init__.py
tools/extractors/lodestone.py
```

`tools/extractors/lodestone.py` must provide at least:

```python
is_lodestone_url(url: str) -> bool
extract_lodestone_article(html: str, url: str) -> dict[str, str]
```

`is_lodestone_url()` should return true for official Lodestone URLs such as:

```text
https://na.finalfantasyxiv.com/lodestone/...
https://eu.finalfantasyxiv.com/lodestone/...
https://jp.finalfantasyxiv.com/lodestone/...
https://de.finalfantasyxiv.com/lodestone/...
https://fr.finalfantasyxiv.com/lodestone/...
```

Expected extractor return shape:

```json
{
  "title": "Patch 7.5 Notes",
  "body": "Patch 7.5 Notes\n...",
  "extractor": "lodestone"
}
```

Recommended error type:

```text
LodestoneExtractionError
```

### Fetch Result Contract

`fetch_single_url()` should include extractor metadata.

```json
{
  "url": "https://...",
  "content_type": "text/html; charset=utf-8",
  "title": "Patch 7.5 Notes",
  "body": "...",
  "extractor": "lodestone"
}
```

Allowed extractor values:

```text
lodestone
generic_html
text
json
```

Exact names may vary only if tests and docs use one stable convention.

### Process Source Action Contract

When `fetch_single_url()` returns `extractor`, `process_source.py` must include it in the `fetch_url` action.

Required action fields:

```text
name
status
url
content_type
extractor
```

Example:

```json
{
  "name": "fetch_url",
  "status": "ok",
  "url": "https://na.finalfantasyxiv.com/lodestone/...",
  "content_type": "text/html; charset=utf-8",
  "extractor": "lodestone"
}
```

If extractor metadata is missing for older helper behavior, the action may omit it or set it to `unknown`, but v05.1 tests should verify it exists for Lodestone.

### Runbook Boundary Contract

`docs/runbooks/process-source.md` must state:

- `process_source.py` is the official source processing entrypoint.
- `markdown_file` source processing must use `process_source.py --local-path`.
- Do not pass a file path string to `ingest_local.py --body`.
- `ingest_local.py --body` expects already-read body text.
- `ingest_local.py` is a low-level helper and not the OpenClaw-facing source processing interface.
- `tools/local_rebuild.py` is a library module.
- Do not run `python tools/local_rebuild.py` expecting rebuild execution.
- Normal rebuild is performed through `tools/process_source.py`.
- `process_source.py` calls `local_rebuild.rebuild_after_ingest()` internally.
- `tools/status_notification.py` builds payloads from final result dicts.
- `tools/status_notification.py` is not a Notion write CLI.
- `process_source.py` only returns a `notion_update` payload.
- OpenClaw or a separate Notion adapter must apply that payload.

Bad example:

```bash
python tools/ingest_local.py \
  --apply \
  --source-type markdown_file \
  --category patch_notes \
  --title "Patch 7.5 Notes" \
  --body "/mnt/d/ffixiv-bot-storage/incoming/patch-7-5.md"
```

Failure explanation:

```text
This stores the path string itself, not the file contents.
```

Correct example:

```bash
python tools/process_source.py \
  --apply \
  --source-type markdown_file \
  --category patch_notes \
  --title "Patch 7.5 Notes" \
  --local-path "/mnt/d/ffixiv-bot-storage/incoming/patch-7-5.md"
```

Required Notion boundary wording:

```text
If result["notion_update"] is present, OpenClaw may apply it to the Notion control/status database.
process_source.py itself does not call the Notion API.
```

## Improvement Proposal Decisions

### Proposal A: Add `ingest_local.py --source-file`

Decision for v05.1:

```text
Do not make this the official OpenClaw path.
```

Reason:

- It duplicates `process_source.py --local-path`.
- It weakens the single official entrypoint rule.
- If it also triggers rebuild, `ingest_local.py` stops being a low-level ingest helper and overlaps with `process_source.py`.

Allowed future option:

- `ingest_local.py --source-file` may be added only as a low-level convenience if it does not trigger rebuild and is clearly documented as internal/debug usage.
- Normal OpenClaw source processing must still use `process_source.py --local-path`.

### Proposal B: Make `local_rebuild.py` CLI-Capable

Decision for v05.1:

```text
Prefer a separate debug CLI over making local_rebuild.py the normal CLI.
```

Recommended path:

```text
tools/rebuild_source.py
```

Reason:

- `local_rebuild.py` is currently a library helper that accepts ingest result dicts.
- A source-id based CLI requires DB lookup and input reconstruction, which is a separate responsibility.
- A separate `rebuild_source.py` keeps library and CLI boundaries clear.

v05.1 requirement:

- Document the issue and boundary.
- Implementing `rebuild_source.py` is optional, not required.

## Relationship to v0.6

v05.1 should be completed before v0.6.

Reason:

- v0.6 automation loop will repeatedly call v0.5 source processing.
- If Lodestone extraction and entrypoint boundaries are unstable, automation will multiply those errors.
- If Notion write boundary is unclear, automation may falsely report status updates that were not applied.
- v05.1 hardening makes v0.6 safer.

v0.6 should start only after:

- Lodestone extraction is tested.
- official entrypoint boundary is documented.
- helper misuse is documented.
- Notion payload/write boundary is documented.
- full regression suite passes.
