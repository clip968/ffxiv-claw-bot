## Goal

`tools/process_source.py`의 URL 처리 결과 action log에 extractor metadata를 포함해 OpenClaw가 어떤 extractor가 사용됐는지 확인할 수 있게 한다.

## Scope

- `fetch_single_url()` result의 `extractor` 값을 `fetch_url` action에 반영
- Lodestone URL processing test 추가
- existing URL integration tests 유지
- Notion payload raw-heavy field exclusion 회귀 확인
- backward-compatible JSON result 유지

Out of scope:

- Lodestone extraction 구현
- fetch routing 구현
- Notion API direct write
- status payload schema 대규모 변경

## Red Test

- File: `tests/test_v05_process_source.py`
- Implementation target: `tools/process_source.py`
- Current red reason: `fetch_url` action does not record Lodestone extractor metadata.

Contracts fixed by the test:

- `process_source.py --apply --source-type url` records `extractor=lodestone` in the `fetch_url` action when fetch result contains that metadata.
- Result JSON still includes existing action fields.
- `notion_update` does not include body/raw HTML/attachments/binary data.

## Key Decisions

- Extractor metadata is diagnostic metadata; it should not force a breaking JSON contract change.
- `process_source.py` must still be the official source processing entrypoint.
- `process_source.py` must not call the Notion API directly.

## Implementation Notes

- If older helper behavior lacks extractor metadata, only Lodestone tests need to require it after v05.1 routing is implemented.
- Keep raw source body out of Notion-facing payloads.
