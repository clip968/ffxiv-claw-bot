## Goal

`tools/fetch_url.py`가 Lodestone HTML URL을 generic HTML extractor보다 Lodestone extractor로 먼저 라우팅하도록 만든다.

## Scope

- Lodestone URL + `text/html` response를 `extract_lodestone_article()`로 라우팅
- non-Lodestone HTML은 기존 generic extraction 유지
- `text/plain`, `application/json`, `+json` 동작 유지
- unsupported content type/error behavior 회귀 방지
- `fetch_single_url()` result에 `extractor` metadata 추가

Out of scope:

- network stack 교체
- recursive crawling
- sitemap parsing
- auth-required URL 처리
- `process_source.py` action metadata, owned by v05.1-05

## Red Tests

- File: `tests/test_v05_fetch_url.py` or `tests/test_v05_1_fetch_url_routing.py`
- Implementation target: `tools/fetch_url.py`
- Current red reason: `fetch_single_url()` does not route Lodestone HTML through a domain-specific extractor and does not return extractor metadata.

Contracts fixed by the tests:

- Lodestone HTML URL returns `extractor=lodestone`.
- Lodestone HTML uses the article body from `.news__detail__wrapper`.
- Non-Lodestone HTML returns `extractor=generic_html`.
- Plain text returns `extractor=text` or the stable convention chosen in implementation.
- JSON returns `extractor=json` or the stable convention chosen in implementation.
- Unsupported content type remains an error.

## Key Decisions

- Lodestone routing belongs in `fetch_url.py`, not in `process_source.py`.
- `process_source.py` should receive normalized fetch metadata from `fetch_single_url()`.
- Generic HTML extraction must remain available for non-Lodestone HTML pages.

## Implementation Notes

- Do not perform real network requests in tests; use the existing mocked fetch pattern from v05 tests.
- Do not add crawler behavior.
