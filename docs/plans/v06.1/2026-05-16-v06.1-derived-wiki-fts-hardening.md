## Goal

Close the v0.6 derived wiki pipeline so `--build-derived-wiki` generates `wiki/jobs/*.md` and immediately indexes those generated job pages into `wiki_fts` in the same source-processing run.

## Scope

- `tools/process_source.py`
  - After successful `generate_derived_wiki.run(...)`, call `tools.compile_wiki.index_wiki_documents(root_path=ROOT, db_path=Path(args.db_path))`.
  - Append an `index_wiki_documents` action to `result["actions"]`.
  - Add `derived_wiki["fts_index"]` with `status` and `summary`.
  - If derived wiki generation succeeds but FTS indexing fails, keep source processing successful and set `derived_wiki.status` to `partial` with `error_stage=derived_wiki_fts_index`.
- Tests
  - Add process-source regression proving direct `--build-derived-wiki` writes `job_gunbreaker` into `wiki_fts`.
  - Add pending-source regression proving `process_pending_sources.py --build-derived-wiki` writes `job_gunbreaker` into `wiki_fts`.
- Docs
  - Update runbooks and handoff to state generated job wiki pages are indexed automatically.

## Out of Scope

- Adding `derived_wiki_status` columns to `source_processing_queue`.
- Changing queue row status semantics beyond existing `derived_wiki_built` / `processed` / error-stage behavior.
- Improving XLSX date, formula, merge, hidden row/column, or inferred-header behavior.
- Renaming the v06 spec file.
